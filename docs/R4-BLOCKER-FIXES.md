# R4 — RC3 阻断问题修复报告

每一项都是：**复现 → 根因 → 修改 → 真实浏览器验证 → 证据**。“证据”是仓库里的文件。没有复现的，明确写“未复现”。**一项未经真人验证的问题都没有被标为“已解决”**；这里的“已修复”只表示：自动化的真实 Chromium 操作验证了。

两条说明：
- 我先按读代码得出的判断做了修改，再在真实浏览器里复现，**其中有一个判断是错的**（第 3 项），报告里如实写出，并给出了更换后的检查。
- “真实键盘”指 Playwright 的 `page.keyboard`（W A S D、E、数字键），与人在键盘上按下的是同一条浏览器事件路径；它不是人的手。

## 2. 火车抓手后人物持续移动

| | |
|---|---|
| 复现 | **已复现。** 撤掉修复后，在真实 Chromium 里用 W + Shift + 空格跑到车门、按 E 抓住琳的手：对话期间身体速度仍是 **4.40 m/s**（位置不变，但奔跑动画按速度播放，所以人在原地一直跑）。`docs/r4-evidence/repro/chase-BEFORE-fix.json`，`c1-hand-dialogue-BEFORE-fix.jpg`。 |
| 根因 | `physics.stepBody` 只在被调用时衰减速度；对话期间 `moveBody` 不再被调用，速度停在抓手那一刻的数值，`syncCast` 用它驱动动画。 |
| 修改 | 任何对话开始时把身体速度清零（`game.js` 的 `dialog()`）。一处修改覆盖所有章节的对话。 |
| 验证 | 同一检查：对话期间速度 0.00 m/s，位置 1.5 秒内移动 0.000 m（`results.json` 的 `chase`）。Node：`v5-r4.test.mjs`“a conversation stops the body”。 |

## 3. 火车对话时绿色模型遮挡

| | |
|---|---|
| 复现 | **我第一个判断是错的。** 读代码后我认为是 `june` 近景把镜头放到离琳 0.48 m 的地方（她的青绿色外套填满画面），于是改了镜头。第一版浏览器检查（只量镜头到身体的距离）在修复前后**都通过**，说明它没有区分度；`docs/r4-evidence/repro/train-BEFORE-fix.json` 就是证据：最近距离 1.48 m，根本没有贴脸。 |
| 真正的根因 | 写了一个“射线探针”（`V5Debug.probeShot`，从相机向说话人的头发射线，报告第一个挡住的物体），再用 `tools/r4-camera-scan.mjs` 扫描：**默认镜头**（没有指定镜头的台词、`seat`、`photoback` 都落在它上）在埃莱娜肩后，**她自己的后脑勺（#4b3568）在 1.42 m 处挡住了琳**，占画面近一半。截图：`docs/r4-evidence/camera/2.train-default-june.jpg`（修复前）。琳的青绿色外套确实在画面里，但它是琳本人，不是遮挡物。 |
| 修改 | 车厢里一旦有对话，所有镜头都用过道固定镜头（`main.js` 的 `shotFor`）：从过道看向说话的人，不穿过任何人的头。游玩时的座位镜头、拍照镜头不变。 |
| 验证 | 扫描：修复前报告 `2.train default june: blocked by elena17 at 1.42 m`（退出码 1，`repro/cameras-BEFORE-fix.txt`）；修复后 `every dialogue close-up is clear`。这一检查现在在 `r4-browser.mjs cameras`、CI 的 R4 任务里。 |
| 仍不确定 | 我无法确认 Owner 看到的“绿色模型”**一定**是这一个镜头。这是目前能复现并实测到的唯一遮挡；如果真人试玩仍看到绿色遮挡，需要他指出是哪一句对话。 |

## 4–7. 光束找琳：A/D 无法完成；关键光点缺失；提示出现但无法过关；接近正确时没有反馈

这四项是同一个问题的四个表现。

| | |
|---|---|
| 复现 | **部分复现，说明范围。** 真实键盘盲按 A 点按（每次 0.12 秒），共 40 次：角度从 1.83 转到 6.85 rad，经过目标窗口（±0.1 rad）时 `onTarget` 只亮过几个采样点，`foundJune` 从未置位。这**只证明“盲按完不成”**；它没有证明“照着屏幕提示按也完不成”，因为 RC3 的屏幕上本来就没有可照着按的提示。画面显示光束是水平的、飞过琳头顶：`docs/r4-evidence/repro/beam-0-start.jpg`、`beam-A-*.jpg`；日志 `beam-log.txt`。“偏差约 0.7 rad”这个数字来自对相机、灯塔、琳三者几何位置的计算（上述截图与之相符），不是实测。 |
| 根因（四处叠加） | ① 画出来的光束水平地飞过琳头顶 6 米，玩家把光对准屏幕上的琳，模拟里的角度却偏了约 0.7 rad，永远落不进 ±0.1 rad 窗口。② 两条光臂都算数，近的那条会在镜头附近扫过，把画面洗白。③ 窗口窄（±0.1）、要持续 0.8 秒、转速恒定，点按几乎必然越过目标。④ 没有任何“目标在哪”“方向对不对”“差多少”的反馈；`ui.beam` 只写“A/D 转动光束”；`snapshot` 里的 `onTarget` 从来没有被画面读过。 |
| 修改 | ① 光臂向下倾斜，照到目标的距离，地面有光圈，目标处有一个金色目标环；琳在礁石上、小屋在沙滩上，环都画在那里。② 只有离目标更近的那条光臂算数，另一条淡出。③ 窗口 ±0.15，持续 0.6 秒，接近目标时转速减半。④ 屏幕上的一行字由游戏状态直接给出：“琳正跑向礁石……” → “把光转向琳——按住 A” → “快到了——轻点 A” → “就是那里——让光停住”。按哪个键由游戏算出（不是屏幕上的左右，那会随光扫过塔而翻转，我第一版就是这样错了一次）。还有：光束镜头移到北侧，塔身不再挡住琳；琳先说“给我十秒——我去礁石那边”，她跑到礁石前 A/D 不会有反应但提示在说明原因。第七章的最后一盏灯（对准旧码头）用同一套。 |
| 验证 | 真实键盘，只按屏幕上那行字说的键，从零开始：找到琳 20–22 秒（含她跑到礁石的时间），再找到小屋约 10 秒；第七章对准码头约 14 秒（`results.json`：`beam`、`town-beam`，截图 `c3-beam-june-*.jpg`、`c3-beam-cottage-*.jpg`）。Node：`v5-r4.test.mjs` 从 4 个不同初始角度用“提示给出的那个键”都能收敛。 |
| 无需外部攻略？ | 是：检查脚本只读屏幕上的那一行字。**不等于“真人不会卡”**：人会按错键、会看别处；需要真人试玩。 |

## 8. 模型穿模和镜头异常

| | |
|---|---|
| 复现 | 全量扫描（`tools/r4-camera-scan.mjs`，9 个有对话镜头的场景，共 40 个镜头×说话人组合，射线从相机到说话人的头）：**4 处有问题**：第二章默认镜头（见第 3 项）；第三章工地玩家近景离琳 **0.44 m**；第七章玩家近景离西奥 **0.46 m**；序章 1998 玩家近景离琳 **0.50 m**。 |
| 根因 | `closeUp` 只避开“别人的头挡在视线上”，不管相机本身离另一个人有多近；换角度时只试 7 个摆动角。 |
| 修改 | 相机必须离其他人至少 0.9 m；试 10 个角度；都不行就选离所有人最远的那个（`main.js` 的 `closeUp`）。 |
| 验证 | 扫描：修改后 0 处（`docs/r4-evidence/camera/scan.json`，`r4-browser.mjs cameras` 通过）。 |
| 没有做 | **不是**完整的穿模审计：这个扫描只查对话镜头的遮挡与相机贴人。人物之间的肢体穿插（比如两个人走过同一个门）、道具穿墙、站位重叠，没有逐一排查，除第四章合奏（RC3 已修）外。真人试玩里看到的穿模，需要逐个报告。 |

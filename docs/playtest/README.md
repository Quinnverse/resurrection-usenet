# V5 blind playtest — facilitator guide · 主持人指南

**Status: no session has been run.** Everything in this folder is the kit; `RESULTS.md` stays empty until real
players have played. Do not fill it with guesses.

状态：尚未进行任何测试。本文件夹只是测试工具包，`RESULTS.md` 在真人试玩之前保持为空，不得填入推测内容。

## What is in the kit

| File | Use |
|---|---|
| `../../dist/resurrection-v5-playtest.zip` (built by `node tools/v5-playtest-pack.mjs`, also a CI artifact) | the game, a local server (`node serve.mjs`), these documents |
| `PLAYER-SHEET.md` | the only thing the player reads before playing (EN/中文) |
| `FEEDBACK-FORM.md` / `feedback-form.html` | questions after the session; the HTML version saves a JSON file |
| `RESULTS.md` | generated by `node tools/v5-playtest-summary.mjs docs/playtest/sessions/*.json` |
| `sessions/` | put each session's two JSON files here (game log + form), named by tester id |
| `../V5-AUDIO-CHECKLIST.md`, `/v5/audio` | the separate listening check |

## Who · 招募

- 5–8 people who have not seen the design documents, the script or any build. Not developers of this project.
- At least 2 who mainly play in Chinese and 2 in English; at least 2 who rarely play 3D games; ideally 1 with a gamepad and 1 on a touch screen (both are experimental).
- Get consent for screen and voice recording. Players are anonymous: use ids like `P01`.

## Before each session · 每场之前

1. Use a fresh browser profile (or private window) so there is no save and no previous playtest log.
2. Run `node serve.mjs`, open `http://127.0.0.1:8098/v5/?playtest=1`.
3. Press F3 once and check the frame rate line appears (bottom left), then F3 again to hide it. Note the GPU it shows.
4. Type the tester id into the field on the title screen. Hand over the keyboard and mouse (or pad / tablet).
5. Start screen + audio recording. Note the start time on paper as a backup.

## During · 进行中

- Say only what `PLAYER-SHEET.md` says. Do not explain the story, the controls or the archive.
- Help only after **3 minutes** without progress, and only with the smallest hint ("try pressing H"). Write down the time, the place and what you said.
- The game asks two 1–5 questions after each chapter. The player answers or skips; do not prompt.
- Note anything the player says aloud (laughing, "what?", "oh no", silence after a scene), with the time.
- If they want to stop, let them. A partial session is still data; mark it unfinished.

## After · 结束后

1. At the end (or in the pause menu, Esc → "Download playtest log") download the game log JSON.
2. The player fills in `feedback-form.html` (about 10 minutes) and downloads its JSON. Paper is fine too.
3. Put both files in `sessions/` as `P01-game.json` and `P01-form.json`. Keep recordings outside the repository.
4. After all sessions: `node tools/v5-playtest-summary.mjs docs/playtest/sessions/*-game.json > docs/playtest/RESULTS.md`.

## What the game log records · 游戏记录的内容

Real time per beat and per chapter, with the pause menu, title and rating screens excluded; every hint shown after
idling and every press of H; idle stretches over 30 s with position and the nearest prompt (likely stuck spots);
retries, falls and refused Tab switches; skipped dialogue; the choices made; frame rate, slow-frame share and worst
frame per beat; JS memory when the browser reports it; which input devices were used; browser, screen, cores, memory
and the GPU name. Nothing is sent over the network; it stays in the browser until downloaded.

## Release thresholds (from `../V5-PLAYTEST-PLAN.md`)

- median first play 35–45 min, reached without padding;
- no chapter with a median of more than 2 stalls;
- at least 70% can say in their own words that June lost her credit and her job, and that the ending restores the credit without changing the 1998 and 2004 versions;
- nobody describes June as only Elena's love interest.

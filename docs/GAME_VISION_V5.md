# RESURRECTION V5 — Product Vision
Status: AUTHORITATIVE DESIGN TARGET, NOT IMPLEMENTATION CLAIM. Supersedes earlier investigation-first gameplay proposals. Branch: design/resurrection-v5.

## Competition promise
**Resurrection**: revive obsolete USENET-era distributed collaboration and an unfinished 1998 game using modern, provenance-aware reconstruction. A playable browser 3D world is generated from parsed archived messages, attachment manifests and build data; it is not merely a retro terminal skin. Fictional sample archives MUST be labeled as such; never represent them as verified historical posts.

**Player promise**: Play a vivid, intimate coastal summer with Elena and June, then experience its absence and rebuild what can be responsibly preserved. Players DO things, not investigate open-ended clues. Historical harm cannot be erased by gameplay.

## Pillars
1. **Resurrection is mechanic**: archive-derived data changes actual scene graph, collision, NPC behavior and version state; show provenance optionally.
2. **Play before exposition**: chase a train, photograph June, cycle, collaborate on the crooked lighthouse window, play original music.
3. **Characters respond**: June proactively invites, waits, jokes, approaches and collaborates; not a static dialogue dispenser.
4. **Versions are emotional**: Tab shifts 1998/2004 historical game builds, showing differences in place and character. The present-day restored edition is a distinct authored layer.
5. **Action has consequence**: visible persistent changes, short feedback loops (2–4 min), meaningful emotion, no dead-end failures.
6. **Ethical authorship**: June's attribution and economic harm are real in story, not excused by love. Correct attribution is mandatory, not a morality toggle.

## Genre, scope, UX
Linear cinematic third-person 3D narrative adventure, target full experience 35–45 min; first delivery an honest 8–10 min vertical slice. Desktop browser first, accessible input alternatives. HUD nearly invisible: transparent contextual prompts, no hard task tabs or intrusive logs. No compulsory archive reading, clue hunts, evidence correlation, inventory fetch quests, combat, gacha, RPG grind, giant open world, compulsory rhythm precision, or misleading fake choices.

## Key distinction
- Historical creator memories: dramatized, evidence-aware scenes, NOT literal time travel or guaranteed recorded facts.
- 1998/2004 *Last Light* builds: executable historical versions derived from surviving data.
- Present restored edition: modern, explicitly attributed and labeled reconstruction/new work.
- Elena and June cannot be resurrected as conscious beings; Theo/Iris are fictional scripted game characters.

## Narrative arc
Playful summer -> mutual affection -> shared creation -> separation -> 2004 authorship dispute -> recognition of harm -> restoration and first winter. The unsent apology remains unsent; June retains independent life and agency. The player can simulate fictional game-character futures but cannot undo real-world history.

## Anti-goals
Do not reintroduce prior M01/M02 investigative identity/evidence puzzles, Tab evidence log, J quest tabs, source-file hunts, or arbitrary photograph alignment puzzles. Evidence and provenance are implementation infrastructure and optional demo UI, not player progression gates.

## Acceptance
A stranger can understand the obsolete-tech resurrection in a 3-minute demonstration and enjoy 10 minutes of genuine interactive play without searching files. Reproducible provenance test confirms that changing archived fixture input changes reconstructed scene state. All claims of implemented features must be checked against actual code and browser execution.
